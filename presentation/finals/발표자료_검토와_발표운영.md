# 발표자료 검토와 발표 운영

## 검토 결론

현재 1~5페이지는 파란 강조색, 그라데이션 배경, 둥근 카드, 굵은 제목이 일관돼 기본 디자인 완성도가 높다. 4분 발표에서는 정보량을 줄이고 실제 사용 흐름을 빨리 보여 주는 편이 좋다. 10분 발표는 기능 설명만 늘리기보다 동작 원리, 검증 범위, 한계, 현장 파일럿 계획을 설명할 때 설득력이 생긴다.

원본 발표자료는 보존했다. 별도 공용 PPTX에 실제 앱 화면과 확장 슬라이드를 추가했다. 확인용 PDF는 검토한 슬라이드 이미지를 담았으며, 편집과 발표자 노트는 PPTX에서 사용한다.

PPTX의 **슬라이드 쇼 → 사용자 지정 슬라이드 쇼**에서 `4분 핵심 발표` 또는 `10분 본선 발표`를 선택한다. 기본 전체 재생은 14장이다. 각 장의 노트에는 시간과 발표 멘트가 있다. 사용자 지정 쇼는 파일 구조와 참조 순서를 검사했으며, PowerPoint 앱에서 직접 실행한 검증은 하지 않았다.

## 1~5페이지 디자인 제안

| 페이지 | 관찰 | 개선 제안 | 우선순위 |
|---|---|---|---|
| 1 표지 | 제품명과 아이콘은 잘 보이지만 부제가 대상·제품 종류 설명에 머무른다. | 차별점을 말하는 “작업 전 안전 공유부터 조치 사진 확인까지”를 보조 문구로 고려한다. 기존 구도는 유지 가능하다. | 중 |
| 2 문제 | 58%의 의미를 TBM 미실시율로 오인할 수 있다. 오른쪽 세 항목과 하단 TBM 설명을 동시에 읽어야 한다. | 수치의 모집단을 바로 아래 명시한다. 세 항목은 “안전 공유 누락 / 조치 기록 분산 / 작업별 수칙 탐색”처럼 짧게 만들 수 있다. TBM 상세 풀이는 10분 설명이나 노트로 보낸다. | 상 |
| 3 위험평가·공유 | 상단 카드와 하단 띠 사이 공백이 커 시선이 끊긴다. 설명과 의무 관련 문구가 중복된다. | “위험을 평가했는가 → 근로자에게 공유했는가 → 조치가 기록됐는가”의 흐름을 중심으로 설명한다. 구체적인 법률 적용 범위는 별도 확인이 필요하다. | 상 |
| 4 경쟁 비교 | 다섯 열의 표, 보조 문구, 해외 참고, 각주가 있어 무대에서 읽기 어렵다. | 10분 전용으로 운영한다. 행 이름을 줄이고 조사 상세는 노트로 옮길 수 있다. 경쟁 서비스 전체를 단정하는 문구보다 관찰·조사 범위를 밝힌다. | 최상 |
| 5 서비스 | 관리자/근로자 구분은 명확하지만 여섯 기능과 사용 구성까지 함께 보여 줘 초점이 분산된다. | “관리자는 전달하고, 근로자는 확인·보고합니다”라는 흐름으로 시연에 연결한다. 점수·연속 기록은 보조 기능으로 설명한다. | 상 |

공통적으로 회색 보조 설명과 출처는 발표장에서 읽기 어려울 수 있다. 핵심은 본문으로 올리고 상세 근거는 노트에 남긴다. 사진 판정은 색상뿐 아니라 텍스트와 기호도 함께 사용하면 구분하기 쉽다.

## 작업본 반영사항

디자인 제안 전체를 재설계하는 대신 앞의 다섯 페이지 디자인은 보존하고 다음 항목을 반영한다.

- 2페이지 수치 설명을 “재해조사 대상 사고사망자 중 / 소규모 사업장·현장 비중”으로 명확히 한다. 원수치는 589명 중 339명으로 57.56%이며 58%는 반올림이다. 원출처의 소규모 구분은 “50인(억) 미만”이므로 건설업 현장을 일괄적으로 “50인 미만”이라고 설명하지 않는다. [고용노동부 원출처](https://www.moel.go.kr/news/enews/report/enewsView.do?news_seq=17595)
- 3페이지의 법적 의무와 조사 절차에 관한 단정적 표현을 줄이고 위험 공유와 기록의 필요성을 설명하는 중립 문구로 정리한다. 발표자료가 법률 자문이나 준법 보증처럼 읽히지 않도록 한다.
- 4페이지의 차별점 문구를 “사진에 보이는 조치 확인을 돕습니다”로 완화한다. 사진만으로 현장 안전 전체를 확인한다는 인상을 피한다.
- 5페이지의 “PLAN”을 “사용 구성”으로 바꿔 현재 사용 방식임을 명확히 한다.
- 페이지 하단 총수를 14장 구성에 맞춘다.
- 4분용 핵심 7장을 별도 사용자 지정 슬라이드 쇼로 구성하고, 발표자 노트에도 4분/10분 운영을 기록한다.

## 최종 슬라이드 구성과 시간

| 장 | 주제 | 4분 | 10분 | 발표 목적 |
|---|---|---:|---:|---|
| 1 | 표지 | 10초 | 15초 | 제품과 한 문장 가치 소개 |
| 2 | 문제 | 30초 | 40초 | 소규모 현장의 안전 공유·조치 기록 문제 |
| 3 | 위험평가·공유 | 건너뜀 | 35초 | 위험평가, 공유, 기록의 연결 |
| 4 | 경쟁 비교 | 건너뜀 | 35초 | 조사 범위 안에서 차별점 설명 |
| 5 | 서비스 | 25초 | 35초 | 관리자와 근로자의 역할 연결 |
| 6 | 입력·체크리스트 | 45초 | 55초 | 작업 입력에서 수칙 확인까지 |
| 7 | TBM | 건너뜀 | 40초 | 음성 기록과 작업 전 공유 흐름 |
| 8 | 사진 검토 | 45초 | 60초 | 사진에 보이는 조치 검토와 판정 한계 |
| 9 | 근로자 보고·관리자 검토 | 40초 | 45초 | 보고가 관리자 확인으로 이어지는 과정 |
| 10 | JSA | 건너뜀 | 35초 | 보고·위험요인·안전조치 초안 검토 |
| 11 | 동작 원리 | 건너뜀 | 50초 | 입력·처리·결과·사람 확인 구조 |
| 12 | 검증 | 건너뜀 | 50초 | 확인된 범위와 미검증 영역 구분 |
| 13 | 도입 | 건너뜀 | 50초 | 사용 구성, 파일럿 계획과 평가 기준 |
| 14 | 결론 | 30초 | 25초 | 제품의 핵심 가치와 다음 단계 |
| 합계 |  | 225초 | 570초 | 각각 15초, 30초 여유 |

4분 발표 순서는 **1 → 2 → 5 → 6 → 8 → 9 → 14**다. 10분 발표는 14장을 모두 사용한다. 4분에서는 건너뛰는 슬라이드 내용을 앞뒤 장에서 전제로 삼지 않아야 한다. 사용자 지정 쇼가 작동하지 않는 환경에 대비해 위 순서를 발표자 노트에도 남긴다.

## 실제 화면 캡처 선정 기준

캡처는 기능 목록보다 한 작업의 시작과 결과를 이어 보여 주도록 고른다. 세로형 휴대폰 화면을 기본으로 하되, 한 장에 너무 많은 화면을 축소해서 배치하지 않는다.

| 슬라이드 | 캡처할 상태 | 화면에서 확인할 내용 |
|---|---|---|
| 6 입력·체크리스트 | 관리자의 작업 입력과 생성된 체크리스트 | 입력한 작업과 출력 수칙의 연결, 필수·권장 또는 근거 표시 |
| 7 TBM | TBM 기록·분석 결과 | 공유한 내용과 누락 검토 결과, 다음 행동 |
| 8 사진 검토 | 사진과 검토 결과가 함께 보이는 상태 | 어떤 사진을 검토했는지, 확인됨·안 보임·판단불가의 구분 |
| 9 보고·검토 | 근로자 보고 화면과 관리자 검토 화면 | 같은 보고가 두 역할의 화면에서 이어지는 흐름 |
| 10 JSA | 보고를 담은 초안과 안전조치 영역 | 작업 내용·위험요인·안전조치의 연결. 현재 별도의 작업 단계 필드는 없음 |

가능하면 같은 작업명과 보고 맥락을 유지한다. 개인정보, 비밀키, 불필요한 개발 도구는 화면에서 제외한다. 로딩이나 빈 화면보다 입력과 결과가 명확한 상태를 선택하고, 결과만 잘라 제품이 실제로 어떤 입력을 받았는지 숨기지 않는다.

실제 캡처 13개는 `captures/`에 보관했다. 슬라이드에는 01·04(6장), 05(7장), 06·07(8장), 10·11(9장), 12·13(10장)을 사용했다. 나머지는 조건 검토·근로자 화면을 설명할 때 교체할 후보이다. 이번 캡처는 390×844 브라우저 뷰포트이며 실제 휴대폰 촬영은 아니다. 예시 용접 사진은 저장소 데이터셋에서 가져왔고, 시나리오 현장의 촬영 사진이 아니다.

휴대폰 전체 화면은 발표장에서 글자가 작아질 수 있다. 전체 화면으로 제품 맥락을 보여 주면서 오른쪽에 핵심 영역 확대본 또는 짧은 설명을 배치한다. 한 장에 휴대폰은 보통 1~2개로 제한하고, 강조 영역을 박스·번호로 표시한다. 확대본은 같은 실제 캡처를 잘라 사용하며 결과 문구를 새로 만들어 화면처럼 넣지 않는다. 세부 텍스트를 읽게 하기보다 “작업 입력 → 수칙 생성”, “사진 제출 → 검토 결과”처럼 변화 한 가지를 말한다.

## 검증과 한계의 발표 방식

- 백엔드 테스트 179개 통과, 프런트엔드 빌드 통과는 소프트웨어 동작 확인 근거다. 현장 안전 효과나 AI 판정 정확도를 증명하는 수치로 사용하지 않는다.
- 발표 캡처는 mock 모드의 실제 앱 화면이다. 화면의 AI 결과는 실제 외부 AI 모델 호출 결과가 아니므로 발표자 노트와 검증 슬라이드에서 구분한다.
- 사진 성능 관련 수치는 검수 전 라벨 기반 결과를 정확도로 제시하지 않는다. 사람 검수 기준과 평가 데이터가 확정된 뒤에 성능 지표를 제시해야 한다.
- 12장의 기존 개발 실험 수치는 `검증근거.json`에 출처 파일 해시와 함께 보관했다. 이번 작업에서는 실제 외부 AI API를 호출하지 않았다.
- 현장 파일럿은 아직 실시하지 않았다. 도입 슬라이드에서는 완료 실적으로 말하지 않고 향후 계획으로 설명한다.
- “안 보임”은 사진에서 확인되지 않았다는 뜻이며 실제 미조치의 확정 판단과 구분한다. “판단불가”는 추가 사진이나 사람 검토로 이어지도록 설명한다.

10분 발표가 충분히 성립하려면 11~13페이지에서 신뢰를 얻어야 한다. 동작 원리에서는 근거와 사람 검토가 어디에 들어가는지, 검증에서는 지금 확인한 범위가 어디까지인지, 도입에서는 현장에서 무엇을 측정할지 설명한다. 파일럿 평가 후보는 체크리스트 작성 시간, 보고·검토 완료율, 추가 확인 요청 빈도, 근로자 사용성 등이다. 아직 측정하지 않은 개선 효과를 숫자로 단정하지 않는다.

## 발표 전 확인

- 4분 사용자 지정 쇼와 10분 전체 쇼를 각각 실행해 슬라이드 전환을 점검한다.
- 무대 화면 비율과 폰트 깨짐 여부를 확인한다.
- 사진 검토의 mock 표시와 한계를 설명하는 발표 멘트를 준비한다.
- 캡처 시연만으로도 발표가 이어지도록 준비하고, 현장 네트워크에 의존하는 라이브 시연은 보조로 운영한다.
- 4분 225초, 10분 570초 기준으로 실제 말하기 리허설을 해 전환 시간을 포함한 총시간을 확인한다.
