# scoring/ — 점수·연속 기록·순위

이 모듈은 안전반장의 점수와 기록 규칙을 한곳에서 처리한다. 라우터가 `score_events`에 직접 기록하지 않고, 반드시 이 모듈의 적립 함수를 호출한다.

## 확정 규칙

| 상황 | 함수 | 점수·제한 |
| --- | --- | --- |
| 사진 증빙이 `confirmed` | `award_evidence` | 항목당 한 번, 10점 |
| 위험 제보 | `award_report` | 횟수 제한 없이 매번 5점 |
| TBM 기록 | `award_tbm` | 작업당 한 번, 3점 |

사진이 `not_visible` 또는 `uncertain`이면 점수를 적립하지 않는다. 따라서 체크만 하거나 판단불가 사진을 제출해도 점수를 받을 수 없다.

배점 10·5·3은 현재 PoC의 임시값이다. 변경은 제품 결정 뒤에 한다.

## 집계 단위

점수 이벤트에는 `worker_id`와 적립 당시의 `team_snapshot`을 함께 저장한다.

- `team_ranking`은 `team_snapshot`으로 집계한다. 작업자가 팀을 옮겨도 과거 기여는 당시 팀에 남는다.
- `worker_ranking`과 `stamps_for`는 개인 누적을 집계한다.
- 스탬프는 첫 사진, 사진 5·20개, 첫 제보·제보 5건, TBM 7회를 제공한다.

## 연속 기록 두 가지

| 기록 | 계산 | 끊기는 조건 |
| --- | --- | --- |
| 참여 연속 기록 | 점수 이벤트 또는 TBM이 있는 날짜를 연속 계산 | 하루 기록이 비었을 때. 단 오늘 아직 기록하지 않았으면 어제까지의 연속을 유지 |
| 무사고 기록 | 현장 첫 작업일 이후의 일수 | 보고하지 않았거나 후속 조치가 끝나지 않은 사고 |

사고를 보고하고 후속 조치를 끝낸 경우에는 무사고 기록을 유지한다. 무사고 일수는 현장 존재 기간을 넘지 못한다.

## 서버 연동

| API | 현재 호출 | 결과 |
| --- | --- | --- |
| `POST /api/evidence` | `award_evidence` | 최종 사진 판정이 `confirmed`일 때만 적립 |
| `POST /api/reports` | `award_report` | 위험 제보 5점 적립 |
| `POST /api/tbm` | `award_tbm` | 작업당 한 번 적립 |
| `GET /api/scores` | 순위·스탬프·연속 기록 조회 | 점수 화면 데이터 반환 |
| `POST /api/incidents` | 사고 기록 저장 | 무사고 기록 계산에 반영 |
| `POST /api/incidents/{id}/follow-up` | 후속 조치 완료 | 무사고 기록 재계산 |

현재 `/api/incidents`는 사고 기록만 저장하고 `award_report`를 호출하지 않는다. 따라서 “아차사고 신고도 항상 가점” 정책을 적용하려면 사고 신고와 제보 점수의 연결 여부를 별도로 결정·구현해야 한다.

## 파일 구성

- `points.py`: 사진·제보·TBM 적립과 중복 방지
- `streaks.py`: 참여·무사고 연속 기록과 최근 14일 기록
- `aggregate.py`: 팀·개인 순위와 스탬프
- `__init__.py`: 화면과 라우터가 쓰는 공개 함수·상수
